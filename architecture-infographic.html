That is why a Teach session started inside a VM shows under local in the Network tab: the VM's browser is a steering wheel; the engine never left the master. Two things change this default: delegated tasks (commands run on the VM, brain on master) and agents inside VMs (everything runs on the VM).

3VMs — the machines you can create, enter, and fill with agents

📦ContainersUbuntu userland on the shared WSL2 kernel. Start in seconds, no desktop. Ideal for agent work and shells. ytl-*
🖥️QEMU VMsBoot their own Linux kernel, virtual disks, a real desktop. Heavier; what you watch and record. proto-agent, laptop-vm-*
🚪Getting inApp: per-sandbox Terminal (bash in the browser). CLI: cua sb exec name -- bash. QEMU desktops: Cua Spaces app / VNC.
♻️Lifecyclecreate · suspend · resume · restart · rm --force. Files persist on the machine's disk across all of it; only processes die on restart.

💠 Agents inside VMs — the endgame, working today.

One click (Install agent) copies the Pi Durable harness into the machine and starts it there. From then on that VM has its own conversations, its own files, its own Kimi calls — the Console tab's "Run on" selector talks to it, and the Network tab lists its sessions under its node. Your master can reboot; the VM's sessions don't notice.

Resume semantics everywhere: every session is a durable conversation. Kill the process mid-answer → the partial stays marked aborted, the next run finishes it. Recreate a VM → re-run Install agent (idempotent); the conversations on its disk are still there.

5The second laptop — external VM host in 3 steps

Copy the folder scripts/laptop-vm from the repo to the laptop.
Prepare (admin PowerShell): Install-VmStack.ps1 — installs cua, enables the hypervisor feature (reboot), fixes the QEMU keymap bug, installs the shim that cures the WHPX crash. Every pitfall from day one, automated.
Create: New-LaptopVm.ps1 -MasterUrl http://192.168.50.111:8471 -Count 3 — up to 5 desktop Ubuntu VMs, each printing how to view it (Cua Spaces app / VNC) and how to join the master (browser → LAN URL + token).
Recording-ready: each VM is a full desktop; capture the Cua Spaces stream or a VNC window with OBS when you want to film what an agent does. Resource rule of thumb: ~4 GB RAM per VM.

6The five laws of the system

1 · Off is off.Durable never loses work and never ghost-runs. Master off → everything waits; VM off → its sessions wait on its disk.
2 · One owner per notebook.Never two agentd processes on one harness.sqlite. It corrupts entry IDs.
3 · Browsers are windows.Whoever and wherever — clicks become master-side work unless the session belongs to an agent on a VM.
4 · The token is the border.Everything on the LAN is behind the LAN token; only loopback gets master powers (⏻ button).
5 · Aborted ≠ deleted.Interrupt anything; the partial stays in the transcript, the next run resumes exactly there.
+1 · Exactly-once.Re-sending a job after a crash returns the original result instead of doing the work twice.

7Security, at a glance

Key chain: your Kimi key sits in agentd/.env on the master (gitignored) and is copied into a VM only when you Install agent there (chmod 600 in the guest) — needed so the VM can call Kimi itself. The LAN token gate protects every API on untrusted networks, the Windows firewall opens only port 8471, and agentd itself never leaves 127.0.0.1 on the master. Guests on your LAN remain yours; don't forward 8471 to the internet.
