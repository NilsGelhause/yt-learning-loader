CUA Spaces — computers for AI agents

What it is, what the pieces do, and how your yt learning app uses it trycua/cua · open source free for individuals

1 · The one-liner

CUA gives AI agents real computers to work on — full desktops and Linux sandboxes they can see, click, type in, and run code on. You decide which agent drives which machine.

Made by Cua AI (trycua). The pitch: “Give AI agents computers they can use.” Instead of an agent only chatting, it gets an actual desktop — screenshot in, keyboard & mouse out — plus terminals, files and code execution. Computer-Use 2.0: one agent moving between code, APIs and graphical apps inside a single task.

2 · The toolbox — the pieces and what each does

🖥️Cua Spaces

The desktop app. Each Space is a full desktop: a macOS VM on your Mac, or a Linux / Omarchy image. Menu-bar app, live screen streams, “teleport” signed-in apps into a Space.

💠cua CLI & SDK

One cua command + SDKs (Python, TypeScript, Rust) for VMs, containers and any machine running the daemon. cua sb create ubuntu --name dev spins up an Ubuntu sandbox.

🧊Lume

Local VM manager for Apple Silicon (macOS & Linux VMs via Apple’s Virtualization framework). SSH-ready, prebuilt images.

🕹️Cua Driver

Drives native desktop apps & browsers on macOS, Windows and Linux — for the machine you are sitting at. CLI, MCP or typed SDKs.

📡cua-spacesd

The in-Space daemon (port 3211). Gives agents processes, files, screenshots, input and low-latency video/audio streaming as soon as a Space starts.

🔑Cua Keyvault

Your sessions (e.g. a teleported Chrome, logged in) stay encrypted on your machine and reach a Space only after you approve.

🧠CUA-S1 models

Small specialized “System 1” decision models for computer use (e.g. which value belongs in a form field). Optional — bring any model.

📊Cua Bench

Build computer-use tasks, evaluate agents, export trajectories for training. Ships a no-VM simulated starter task.

3 · Multiplayer & teleport — the magic bits

🖱️ Multiplayer desktops.

You and your agent share the same desktop, each with your own cursor. Step in to make a choice, then hand the desktop back. Like the Network tab idea — several actors, one machine.

🚀 Teleport.

Move a signed-in app (Chrome, Slack…) into a Space and it opens there, still signed in. Credentials live in the encrypted Keyvault on your Mac and only cross over after your explicit approval.

5 · Install & first sandbox

Windows (PowerShell)
irm https://cua.ai/install.ps1 | iex
macOS / Linux
curl -fsSL https://cua.ai/install.sh | sh
1Install the cua CLI. The installer explains itself; the CLI is always installed, the Spaces desktop app is optional (macOS default).
2Create an Ubuntu sandbox: cua sb create ubuntu --name ytl-1 · run commands with cua sb exec ytl-1 uname -a · screenshot with cua sb screenshot ytl-1.
3Clean up: cua sb rm ytl-1. Nothing persists unless you want it to.
Honest platform notes. The polished Spaces desktops are a macOS story today (VMs via Apple’s hypervisor). On Windows, the scriptable path is the cua CLI with Ubuntu sandboxes (gVisor-isolated containers — WSL2 required). Windows/Linux builds of the full Spaces app exist (Tauri) but are newer. In this project we use the CLI path: your VMs are Ubuntu sandboxes that join the webapp as clients.
