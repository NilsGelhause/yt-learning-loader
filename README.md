# YT Learning Loader

A self-contained local learning webapp: scrape YouTube channels, let an AI
agent turn videos into structured learnings and interactive lessons, and
build a personal skill library from what you've learned. Python standard
library only — no frameworks, no build step, one folder, runs locally.

## What it does

- **Scrapes YouTube** — add single video URLs or whole channels; downloads
  metadata, thumbnails, and transcripts (yt-dlp + the Innertube API).
- **AI-extracted learnings** — per video: summary, skills, key points with
  timestamps, and a mermaid diagram, generated by a local agent (Kimi Code
  CLI). Skill names are auto-normalized against a canonical taxonomy so the
  library stays distinct as it grows.
- **Teach Me workspaces** — freestyle topics or whole videos. An agent
  interviews you about your goals, confirms a mission, then builds numbered,
  self-contained HTML lessons (with quizzes, exercises, and cheat sheets)
  that open right in the app. Finished workspaces become installable
  `SKILL.md` files.
- **Skill library** — "Known skills" (from learned videos + distilled
  workspace skills) vs "skills to learn", with one-click teach-me jumps;
  skills install into `~/.kimi-code/skills` for use in any agent session.
- **11 tabs** — Overview, Teach Me, Visualization (mermaid diagrams with
  zoom), Relationships (cross-video skill graph), Videos (sortable table +
  scraping jobs), Learned, My Skills, Profile, Tests (in-app test runner),
  Structure (file map with peek-inside previews), Settings.

## Quickstart (Windows)

```bat
start.bat
```

or manually:

```bat
.venv\Scripts\python.exe launch.py    :: runs the test suite, then serves
```

Then open http://127.0.0.1:8471 (the browser opens automatically).
Requires Python 3.15 in `.venv` (already present).

## LAN clients (VMs & other devices)

By default the app binds `127.0.0.1` — only this machine can use it. To let
other devices or VMs on your network reach it:

1. **Settings tab → "LAN / other devices"**: set **Host** to `0.0.0.0`
   (restart required) and optionally set a **LAN token**.
2. **Windows firewall**: allow inbound TCP on the port (default 8471) —
   Settings → Privacy & security → Windows Security → Firewall → "Allow an
   app", and allow `python.exe`; or from an elevated prompt:

   ```bat
   netsh advfirewall firewall add rule name="YT Learning Loader" dir=in action=allow protocol=TCP localport=8471
   ```

3. **What clients see**: after restart the server prints the URLs to open,
   e.g. `http://192.168.1.50:8471`, and the Settings tab shows them in a
   read-only panel (`GET /api/lan`). If a token is set, clients are prompted
   for it once per browser tab (sent as the `x-ytl-token` header; the
   `?token=` query param works too — handy for sharing links).

**Security note**: the app can run agent shell commands (the Console tab and
teach workspaces drive a coding agent), so exposing it to a network means
exposing that power. On any network you don't fully trust, set a LAN token;
on a trusted home LAN it stays optional. The agentd sidecar itself always
stays on `127.0.0.1` regardless — only server.py gets exposed, and the token
gate covers every `/api/` route. Everything still stays inside your LAN; no
traffic leaves the machine except to the model provider as before.

## The AI agent (Pi Durable sidecar + CLI fallback)

Agent features (teach workspaces, learnings generation, skill distillation)
prefer the **agentd sidecar** in `agentd/` — a Node host for the Pi Durable
agent harness with long-lived model conversations. The app starts it
automatically (`npx tsx src/server.ts`, port `agentd_port` in settings,
default 8472; boot log in `data/agent/agentd.boot.log`). Put a
`KIMI_API_KEY` in `agentd/.env`; `agentd/quickstart.ts` is a standalone
end-to-end demo of the harness. When the sidecar or its key is unavailable,
everything falls back to the [Kimi Code CLI](https://www.kimi.com/code) on
PATH — the Tests tab and the teach-tab console badge show which backend is
active.

## Running the tests

```bat
.venv\Scripts\python.exe tests\run.py
```

226 tests: server endpoints, scraper helpers, workspace/agent flows, the
agentd sidecar integration (stub sidecar, no Node needed), the skill
taxonomy guard, file-preview API, LAN client mode (token auth, /api/lan) —
plus a JS smoke test that renders every tab of the UI against a stubbed DOM
(`node tests/js_smoke.js`).

## Layout

```
server.py            stdlib HTTP server: JSON API + static files + agent jobs
agentd_client.py     stdlib HTTP client for the agentd sidecar (auto-spawn)
agentd/              Node sidecar: Pi Durable agent harness (see above)
scraper.py           channel/video metadata, transcripts, thumbnails
launch.py            test-then-serve launcher used by start.bat
static/js/           one file per tab + core.js (shared helpers, no framework)
static/styles.css    the whole design system
data/                videos.json index, learnings/, (gitignored: thumbs,
                     transcripts, logs, runtime state)
teach/<id>/          teaching workspaces (MISSION.md, lessons/, agent console
                     state) — gitignored, personal
skills/<slug>/       reusable SKILL.md files created from videos/workspaces
tests/               unittest suite + test runner + JS smoke harness
```

## Data & privacy

Everything is local by design. `data/videos.json` and `data/learnings/` are
tracked in git as a backup of the curated library; thumbnails, transcripts,
server logs, and `teach/` workspaces (they contain your learner profile)
are gitignored and never leave the machine.
