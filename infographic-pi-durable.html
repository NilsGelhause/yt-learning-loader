2 · What “durable” actually means

It never loses its place. It also never runs in the background.

Think of a notebook: the agent writes down every step as it goes. If the power dies, the notebook survives on disk. The next time anything — you, the app, a future laptop — opens it, the work continues from the exact line where it stopped. Durable = the notebook. Somebody still has to pick it up.

Evening. A 6-video analysis batch is running. 3 videos done, 3 in flight.
You shut the PC down. Everything stops — instantly. Nothing keeps running. The 3 in-flight videos freeze mid-word.
Overnight. Zero progress, zero cost, zero loss. The notebook on disk remembers exactly: 3 done, 3 half-written.
Morning. start.bat → the harness reopens its notebook, finishes the interrupted tasks, and the batch completes. No redo of the 3 done videos.
Off is off. Durable never loses work — but it never ghost-runs either. Finish = stop + survive + resume on the next start.

3 · What is durable (and what is not)

🎓Teach console

One persistent conversation per workspace. Remembers every turn across restarts.

🔍Scrape analysis

Batch conversations, no timeout. A crash mid-batch resumes, never restarts the batch.

⚗️Skill distillation

Rewriting skills/<slug>/SKILL.md survives interruptions too.

⌨️Consultant console

The standalone “ask anything” agent tab. Same notebook, same rules.

Not durable: the kimi terminal (the CLI you chat with in a console) is a separate program with its own memory — it never touches the harness. Rule of thumb: browser app = durable · terminal kimi = regular.

4 · The rules that keep it healthy

  • One owner per storage. Never run two sidecars on harness.sqlite at once — it corrupts entry IDs. One process owns the notebook.
  • Exactly-once. Re-sending the same job after a crash returns the original result instead of doing the work twice.
  • Aborted ≠ deleted. Killed mid-answer? The partial stays in the transcript marked stopReason=aborted, next to the finished rerun.
  • Key lives in agentd/.env (KIMI_API_KEY, gitignored). Bad key? The app silently falls back to the kimi CLI — the “kimi CLI” badge tells you.
  • Look inside: npx tsx inspect.ts teach:<workspace> reads any conversation, safely, while the app runs.
  • Feel it: npx tsx quickstart.ts “write a long essay…” → Ctrl+C mid-answer → run the same command again → watch it finish.
